# Center 框架开发教程

本教程基于重构后的 `Center/` 框架源码，按**从简单到复杂**、**从局部到全局**的顺序组织四条主线：

1. **实例行为**：挂在实体上、有预制体、有数据（`isGlobal=false`）。
2. **全局行为**：不依赖实体、不加载预制体、直读 `Global` 静态数据（`isGlobal=true`）。
3. **UI 行为**：继承 `UIBehavior`，走 UI 事件泵与 `UICenter` 缓存。
4. **全局启动**：`GlobalConter` 引导时序、状态机、全局脚本如何被拉起。

> **当前工程状态提示**：框架管线（特性扫描 → 注册 → 工厂实例化）代码已就位，但**现有业务类（PlayerBehavior、LevelBuildBehavior、UIManagerBehavior 等）尚未补打 `[AutoRegisterBehaviour]`/`[AutoRegisterConfig]` 特性**。本教程描述的是**新内容的正确写法**；存量旧类的迁移需 owner 授权后统一处理（见 `Center/Framework.md` 第 7 节）。

## 0. 开工前必须理解的四件事

### 0.1 三层分离

| 层 | 位置 | 职责 | 能不能有 Update |
|---|---|---|---|
| 数据 Data | `Data/` | 字段 + 只读属性 + 得失函数（`Heal`/`ApplyDamage`） | 不能 |
| 逻辑 Logic | `Action/…` | 纯 C# 类，被行为持有，做算法/状态机 | 可以，但靠行为喂帧 |
| 行为 Behavior | `Action/…` | 继承 `Objectbehavior`/`UIBehavior`，订阅事件、创建逻辑 | 订阅 `UpdateEvent` 驱动 |

### 0.2 事件泵（Unity 生命周期 → EventCenter 广播）

```
SingleMono.Update()       → EventCenter.Broadcast("UpdateEvent")
SingleMono.FixedUpdate()  → EventCenter.Broadcast("FixedUpdateEvent")
SingleUIMono.Update()     → EventCenter.Broadcast("UIUpdateEvent")
SingleUIMono.FixedUpdate()→ EventCenter.Broadcast("UIFixedUpdateEvent")
```

**行为自己不继承 MonoBehaviour**，靠在 `LogicAwake` 里 `Subscribe` 这些事件获得帧驱动，在 `LogicDestroy` 里 `Unsubscribe`。

### 0.3 工厂三段式

```
[AutoRegisterBehaviour("Key")] 特性
        ↓
AssemblyScanner 扫描
        ↓
BehaviourTypeRegistry  注册 key→Type + 缓存 isBuild/isGlobal
        ↓
BehaviourFactory      构造（LoadData → LoadSync(prefab) → new → Init → LogicAwake）
        ↓
BehaviourInstanceHub  仓库（_behaviourStack 运行栈 + _pendingBehaviours 待注入区）
```

### 0.4 两个标志

| 标志 | 含义 |
|---|---|
| `isBuild = true` | 启动时随 `BootstrapInitialBehaviours` 自动实例化 |
| `isGlobal = true` | 全局逻辑行为：**不加载预制体、不绑数据、`g_obj=null`、`date=null`**，直读 `Global` 静态类 |

## 1. 教程 A：实例行为（有实体、有预制体、有数据）

以「敌人 Enemy」为例，需要在场景里跑一个会移动、有血条的实体。

### A.1 写数据类 `Data/EnemyData.cs`

继承 `BasicDate`，打 `[AutoRegisterConfig("Key")]`：

```csharp
using System;
using UnityEngine;

[AutoRegisterConfig("Enemy")]
[Serializable]
public class EnemyData : BasicDate
{
    [SerializeField] private int health = 3;
    [SerializeField] private float moveSpeed = 2f;

    public int Health => health;
    public float MoveSpeed => moveSpeed;

    public void ApplyDamage(int amount) => health = Mathf.Max(health - amount, 0);
    public void Heal(int amount) => health += amount;
}
```

### A.2 写逻辑类 `Action/GameBehavior/EnemyLogic.cs`

纯 C#，被行为持有：

```csharp
using UnityEngine;

public class EnemyLogic
{
    private readonly EnemyData _data;
    private readonly Transform _self;
    private Transform _target;

    public EnemyLogic(EnemyData data, Transform self)
    {
        _data = data;
        _self = self;
    }

    public void SetTarget(Transform target) => _target = target;

    public void MoveTick(float dt)
    {
        if (_target == null || _data.Health <= 0) return;
        Vector3 dir = (_target.position - _self.position).normalized;
        _self.Translate(dir * _data.MoveSpeed * dt);
    }
}
```

### A.3 写行为类 `Action/GameBehavior/EnemyBehavior.cs`

继承 `Objectbehavior`，打 `[AutoRegisterBehaviour("Key")]`，构造器里设 `isBuild=true`：

```csharp
using UnityEngine;

[AutoRegisterBehaviour("Enemy")]
public class EnemyBehavior : Objectbehavior
{
    private EnemyData _data;
    private EnemyLogic _logic;

    // 启动时自动实例化
    public EnemyBehavior() { isBuild = true; }

    public override void Init(GameObject obj, BasicDate objectDate)
    {
        base.Init(obj, objectDate);            // 注入 g_obj / date
        _data = (EnemyData)objectDate;
        _logic = new EnemyLogic(_data, obj.transform);
    }

    public override void LogicAwake()
    {
        EventCenter.Instance.Subscribe("FixedUpdateEvent", OnFixedUpdate);
        EventCenter.Instance.Subscribe("PlayerFound", OnPlayerFound);
    }

    public override void LogicDestroy()
    {
        EventCenter.Instance.Unsubscribe("FixedUpdateEvent", OnFixedUpdate);
        EventCenter.Instance.Unsubscribe("PlayerFound", OnPlayerFound);
    }

    private void OnFixedUpdate() => _logic.MoveTick(Time.fixedDeltaTime);

    private void OnPlayerFound(GameObject player) => _logic.SetTarget(player.transform);
}
```

### A.4 放资源

- **预制体**：`Assets/Resources/Enemy.prefab`（文件名 = 注册 key）。
- **配置表**（可选）：`Assets/Resources/Config/enemy.json`，键名与序列化字段一致：

```json
[
  { "index": 0, "name": "Enemy", "health": 5, "moveSpeed": 3.0 }
]
```

配置缺失时自动回退到 `EnemyData` 字段默认值（config-first）。

### A.5 它是怎么跑起来的

```
GlobalConter.Initialize()
  → AssemblyScanner.ScanBehaviours()     // 发现 [AutoRegisterBehaviour("Enemy")]
  → BehaviourTypeRegistry 缓存 isBuild=true
  → BootstrapInitialBehaviours()
      → SetGameObject("Enemy")
          → LoadData("Enemy")            // 读 Config/enemy.json 或 new EnemyData()
          → ResCenter.LoadSync<GameObject>("Enemy")   // 加载 Resources/Enemy.prefab
          → Instantiate(prefab)
          → new EnemyBehavior()
          → Init(instance, data)          // g_obj=实例, date=data
          → LogicAwake()                  // 订阅 FixedUpdateEvent
          → Hub.AddBehaviour(behaviour)  // 入运行栈
```

## 2. 教程 B：全局行为（`isGlobal=true`，不依赖实体）

以「计分管理」为例：不需要场景物体，只在内存里累计分数。

### B.1 不需要写数据类

`isGlobal=true` 时工厂**不加载预制体、不绑 BasicDate**，`g_obj=null`、`date=null`。数据直读 `Global` 静态类。

先在 `Center/global/Global.cs` 里加一个全局字段（如已有可跳过）：

```csharp
public static class Global
{
    public static int TotalScore = 0;
    public static GameEnum CurrentState = GameEnum.Menu;
    // ……其他已有字段
}
```

### B.2 写全局行为 `Action/GameBehavior/ScoreManagerBehavior.cs`

```csharp
using UnityEngine;

[AutoRegisterBehaviour("ScoreManager")]
public class ScoreManagerBehavior : Objectbehavior
{
    // 两个标志都要 true：启动自动跑 + 全局不建实体
    public ScoreManagerBehavior()
    {
        isBuild = true;
        isGlobal = true;
    }

    // isGlobal=true 时 obj=null, objectDate=null，base.Init 会把 g_obj/date 置 null
    public override void Init(GameObject obj, BasicDate objectDate)
    {
        base.Init(obj, objectDate);
        // 不要在这里访问 obj.transform，obj 是 null！
    }

    public override void LogicAwake()
    {
        EventCenter.Instance.Subscribe("EnemyKilled", OnEnemyKilled);
        EventCenter.Instance.Subscribe("GameStart", OnGameStart);
    }

    public override void LogicDestroy()
    {
        EventCenter.Instance.Unsubscribe("EnemyKilled", OnEnemyKilled);
        EventCenter.Instance.Unsubscribe("GameStart", OnGameStart);
    }

    private void OnGameStart() => Global.TotalScore = 0;

    private void OnEnemyKilled(int reward) => Global.TotalScore += reward;
}
```

### B.3 与实例行为的区别

| 对比项 | 实例行为（教程 A） | 全局行为（本教程 B） |
|---|---|---|
| `isGlobal` | `false` | `true` |
| 需要预制体 | 需要 `Resources/Enemy.prefab` | **不需要** |
| 需要数据类 | 需要 `EnemyData` | **不需要**，直读 `Global` |
| `g_obj` | 预制体实例 | `null` |
| `date` | 配置数据 | `null` |
| 典型用途 | 敌人、玩家、背景、道具 | 计分、全局计时、事件总线钩子、会话状态 |

### B.4 它是怎么跑起来的

```
BootstrapInitialBehaviours()
  → SetGameObject("ScoreManager")
      → InstantiateBehaviour(type, null, null)   // 注意 obj=null, data=null
          → new ScoreManagerBehavior()
          → Init(null, null)
          → LogicAwake()                  // 订阅事件
          → Hub.AddBehaviour(behaviour)
```

工厂不会去 `ResCenter.LoadSync<GameObject>("ScoreManager")`（因为 `isGlobal=true` 分支直接 return null）。

## 3. 教程 C：UI 行为（继承 `UIBehavior`）

以「主菜单面板 MainPanel」为例。

### C.1 写 UI 行为 `Action/UIBehavior/MainPanelBehavior.cs`

```csharp
using UnityEngine;
using UnityEngine.UI;

[AutoRegisterBehaviour("MainPanel")]
public class MainPanelBehavior : UIBehavior
{
    public MainPanelBehavior() { isBuild = true; }   // 作为主 UI，启动时打开

    private Button _startBtn;
    private Button _quitBtn;

    public override void Init(GameObject obj, BasicDate objectDate)
    {
        base.Init(obj, objectDate);
        // 从预制体上抓控件
        _startBtn = obj.transform.Find("StartBtn").GetComponent<Button>();
        _quitBtn  = obj.transform.Find("QuitBtn").GetComponent<Button>();
    }

    public override void LogicAwake()
    {
        base.LogicAwake();    // 必须调：自动订阅 UIUpdateEvent / UIFixedUpdateEvent
        _startBtn.onClick.AddListener(OnStartClick);
        _quitBtn.onClick.AddListener(OnQuitClick);
    }

    public override void LogicDestroy()
    {
        base.LogicDestroy();  // 必须调：自动退订
        _startBtn.onClick.RemoveListener(OnStartClick);
        _quitBtn.onClick.RemoveListener(OnQuitClick);
    }

    // 重写 UI 生命周期钩子（基类已自动在 IsVisible=false 时跳过）
    public override void OnUIAwake()  { /* 面板第一次创建时跑一次 */ }
    public override void OnUIUpdate() { /* 每帧，隐藏时基类自动 return */ }
    public override void OnShow()     { /* 每次 OpenUI 时 */ }
    public override void OnHide()     { /* 每次 CloseUI 时 */ }

    private void OnStartClick()
    {
        EventCenter.Instance.Broadcast("RequestGameStart");
    }

    private void OnQuitClick()
    {
#if UNITY_EDITOR
        UnityEditor.EditorApplication.isPlaying = false;
#else
        Application.Quit();
#endif
    }
}
```

### C.2 放 UI 预制体

`Assets/Resources/MainPanel.prefab`，文件名 = 注册 key。

### C.3 UI 是怎么跑起来的

```
GlobalConter.Initialize()
  → OpenMainUI()
      → 遍历 Registry，找第一个 UIBehavior 子类且 isBuild=true 的 key（"MainPanel"）
      → UICenter.OpenUI("MainPanel")
          → 缓存未命中
          → BehaviourFactory.BuildUI("MainPanel")
              → LoadSync<GameObject>("MainPanel")
              → Instantiate(prefab)
              → new MainPanelBehavior()
              → Init(uiRoot, data)
              → LogicAwake()
              → 返回 UIBehavior
          → UICenter.UICache["MainPanel"] = { RootObj, UiBehavior }
          → RootObj.SetActive(true)
          → UiBehavior.OnShow()
```

后续打开其他面板：

```csharp
// 任意地方
UICenter.Instance.OpenUI("SettingPanel");   // 首次加载，之后走缓存
UICenter.Instance.CloseUI("SettingPanel");  // 只 SetActive(false)，不销毁
```

### C.4 UI 行为的铁律

- **必须继承 `UIBehavior`，不要直接继承 `Objectbehavior`**——否则不会自动订阅 UI 泵，也不会被 `OpenMainUI` 识别。
- `LogicAwake` / `LogicDestroy` 里**必须调 `base.LogicAwake()` / `base.LogicDestroy()`**，否则事件不退订。
- 帧更新重写 `OnUIUpdate()`，不要自己订阅 `UIUpdateEvent`（基类已订阅并多态转发）。
- 业务帧更新走 `OnUIUpdate`，逻辑帧走 `OnUIFixedUpdate`。

## 4. 教程 D：全局启动脚本（GlobalConter + 状态机）

「全局脚本」指**场景启动时自动跑、不需要你手动挂物体**的引导代码。

### D.1 启动时序（真实）

```
Unity 启动
  → 首次访问 SingleMono.Instance
    → new GameObject("SingleMono") + AddComponent<SingleMono>()
      → SingleMono.Awake()
          ├─ EnsureGlobalConterCreated()
          │    → new GameObject("GlobalConter") + AddComponent<GlobalConter>()
          │       → GlobalConter.Awake()
          │          └─ Initialize()
          │               1. SingleMono / SingleUIMono 事件泵就绪
          │               2. AssemblyScanner.ScanBehaviours() / ScanConfigs()
          │               3. BootstrapInitialBehaviours()       // 实例行为 + 全局行为
          │               4. OpenMainUI()                      // 主 UI
          │               5. GameStateMachine.Initialize()     // 状态机
          ├─ RegisterEvent: Awake/Start/Update/FixedUpdate/OnDestroy
          └─ Broadcast("AwakeEvent")
```

### D.2 你需要做什么？

**什么都不用做。** 框架没有 `[RuntimeInitializeOnLoadMethod]`，但 `SingleMono` 是懒加载单例——你只需要保证：

- 场景里**不要**手动挂 `SingleMono`/`SingleUIMono`/`GlobalConter`（会被自动创建并 DontDestroyOnLoad）。
- 所有行为打了 `[AutoRegisterBehaviour]`，数据类打了 `[AutoRegisterConfig]`。

启动后所有 `isBuild=true` 的行为（实例的、全局的、UI 的）自动就位。

### D.3 状态机怎么用

`GameStateMachine` 已经在 `GlobalConter.Initialize()` 里启动。它注册了这些事件：

| 事件 | 载荷 | 何时广播 |
|---|---|---|
| `GameStateChanged` | `GameEnum` | 任意状态流转 |
| `GameStart` | 无 | 状态切到 Playing |
| `GamePause` | 无 | 切到 Paused |
| `GameOver` | 无 | 切到 GameOver |
| `RequestGameStart` | 无 | UI 按钮触发，状态机内部订阅 |
| `RequestGameOver` | 无 | 外部请求结束 |

业务代码里直接广播：

```csharp
// 主菜单点开始
EventCenter.Instance.Broadcast("RequestGameStart");

// 玩家死亡
EventCenter.Instance.Broadcast("RequestGameOver");
```

监听状态：

```csharp
EventCenter.Instance.Subscribe<GameEnum>("GameStateChanged", OnStateChanged);
EventCenter.Instance.Subscribe("GameStart", OnGameStart);

private void OnStateChanged(GameEnum newState) { /* …… */ }
```

### D.4 全局退出/场景切换

场景切换时如需清空行为栈与 UI：

```csharp
GlobalConter.Instance.DestroyAllBehaviours();
// 内部等价于：
//   BehaviourInstanceHub.Instance.DestroyAll();   // 遍历栈调 LogicDestroy + ClearAll
//   UICenter.Instance.DestroyAllUI();           // 退订 + Destroy 物体 + 清缓存
```

## 5. 碰撞/触发桥接（补充）

桥接类 `CollisionBridge2D/3D`、`TriggerBridge2D/3D` 是普通 MonoBehaviour，**不打特性、不走工厂**：

1. 直接挂到场景/预制体物体上。
2. 通过 `BindEnterEvent` 等注册回调。
3. 行为侧拿到桥接引用后 `BindEnterEvent(OnTouch)`，在 `LogicDestroy` 里 `UnbindEnterEvent`。

```csharp
// 行为里
private void OnTriggerEnter(Other other) { /* …… */ }

public override void LogicAwake()
{
    var bridge = g_obj.GetComponent<TriggerBridge2D>();
    bridge?.BindEnterEvent(OnTriggerEnter);
}

public override void LogicDestroy()
{
    var bridge = g_obj.GetComponent<TriggerBridge2D>();
    bridge?.UnbindEnterEvent(OnTriggerEnter);
}
```

## 6. 关键约定（写代码前过一遍）

- 数据类只放字段 + 得失函数，**不写** Update/状态机。
- 行为只做「绑定数据 → 创建逻辑 → 订阅事件 → 销毁退订」，不写算法。
- 订阅写在 `LogicAwake`，退订写在 `LogicDestroy`，成对出现。
- UI 行为必须继承 `UIBehavior`，并调 `base.LogicAwake()` / `base.LogicDestroy()`。
- 全局行为 `isGlobal=true` 时**不要访问 `g_obj.transform`**（`g_obj` 是 null）。
- 资源一律经 `ResCenter.LoadSync/LoadAsync`，句柄用完必须 `Release()`。
- 跨脚本通信一律走 `EventCenter`，不直接 new 其它行为。
- 配置一律走 `ConfigCenter`，不直接读 JSON。
- `Center/` 目录不新增业务代码，只修 bug。

## 7. 快速对照速查表

| 我要做什么 | 继承 | 打特性 | 关键标志 | 需要预制体 |
|---|---|---|---|---|
| 玩家/敌人/道具（有实体） | `Objectbehavior` | `[AutoRegisterBehaviour("X")]` | `isBuild=true` | `Resources/X.prefab` |
| 计分/全局计时/会话状态 | `Objectbehavior` | `[AutoRegisterBehaviour("X")]` | `isBuild=true; isGlobal=true` | **不需要** |
| UI 面板 | `UIBehavior` | `[AutoRegisterBehaviour("X")]` | `isBuild=true` 作主 UI | `Resources/X.prefab` |
| 后加载实体（关卡里动态生成） | `Objectbehavior` | `[AutoRegisterBehaviour("X")]` | `isBuild=false`，外部 `InjectBehaviour("X")` | `Resources/X.prefab` |
| 碰撞/触发回调 | 挂 `TriggerBridge2D` 等 | **不打特性** | — | 挂在场景物体上 |

#总结

本版开发教程按四条主线重写：① **教程 A 实例行为**（Enemy：数据+逻辑+行为+预制体+配置 JSON 全链路）；② **教程 B 全局行为**（ScoreManager：`isGlobal=true` 不建实体、直读 `Global`、与实例行为的对照表）；③ **教程 C UI 行为**（MainPanel：继承 `UIBehavior`、控件绑定、`OnUIUpdate` 钩子、`OpenMainUI` 启动链路）；④ **教程 D 全局启动**（SingleMono→GlobalConter 嵌套 Awake 时序、状态机事件表、`DestroyAllBehaviours` 全局退出）。结尾附快速对照速查表，一眼查"我要做什么该怎么写"。

> 声明：本教程所有代码示例与启动时序均对齐重构后的 `Center/` 源码（`GlobalConter.OpenMainUI`、`BehaviourInstanceHub.DestroyAll`、`BuildUI` 返回 `UIBehavior`、接口仅保留 `Init(GameObject, BasicDate)`）；未修改任何业务代码，存量行为类补打特性需 owner 授权后执行。
